# QA — BASEADO EM RISCO

Prioridade de teste neste projeto:

1. Isolamento multi-tenant (vazamento entre imobiliárias = pior bug possível)
2. Autorização por papel (ADMIN / GERENTE / CORRETOR / CLIENT / OWNER)
3. Integridade de dados (leads, propostas, financeiro, locação)
4. Regras de negócio (abaixo)
5. Jornadas críticas (site → lead → funil → proposta → contrato)
6. UI / secundário

## REGRAS DE NEGÓCIO VIGENTES (não invente outras)

- Rodízio de leads: imóvel com corretor ATIVO vinculado → lead vai para ele
  (`fromProperty`); rodízio justo é fallback; timeline registra o motivo.
- Lead de imóvel SOLD/RESERVED: cria normalmente, mantém vínculo, nota
  automática de aviso (+ `wantSimilar`) e pill na ficha.
- Visitas só em imóveis disponíveis; datas passadas bloqueadas.
- Locação: repasse ao proprietário SÓ após pagamento (aluguel − taxa adm).
- Portal do cliente: proposta só em negociação aberta (não WON/LOST) do
  PRÓPRIO contato; avança funil para PROPOSAL com STAGE_CHANGE.

Se um comportamento não puder ser determinado pelo código, banco ou docs,
reporte: **BUSINESS RULE REQUIRES CONFIRMATION** — não presuma.

## TESTES NEGATIVOS OBRIGATÓRIOS EM FLUXO CRÍTICO

- id de outro tenant / de outro contato (posse) → deve falhar sem efeito
- sessão expirada ou papel errado → redirect correto (/login, /painel, /cliente)
- input inválido/malformado/vazio · duplicidade · datas passadas
- valores monetários: "R$ 1.250,50" (texto do MoneyInput), vazio, zero, negativo
